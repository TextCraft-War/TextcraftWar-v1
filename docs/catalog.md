# 键表：落库的稳定编码

> 状态：草案（v1 物品清单已定，建筑清单待定）｜ 最后更新：2026-10-30
>
> 相关：[data-model.md](./data-model.md)、[decisions.md D25](./decisions.md)

## 一、这一页解决什么

库里有一批 `TEXT` 列，值的含义完全靠约定：`库存.物品`、`地区建筑.建筑`、
`库存.所有者类型`、`平台绑定.平台`、`玩家.联军职务`。

**这些值是稳定键，不是显示名。** 一旦写进库就不许改——改一次就要动全部历史数据。
所以先把词表定死，之后写代码、写迁移、跟 Koishi 插件对齐都照这一页来。

三条规则：

1. **编码只增不改。** 要改名只改中文显示名，编码不动。
2. **废弃用标记，不删行。** 老数据里可能还有这个编码，删了会让 `TryFrom` 变成"数据损坏"。
3. **不在数据库里加 CHECK 约束。** 加一种物品只需改代码；写成 CHECK 的话，
   每次加物品都要一次 `ALTER TABLE`（还要全表校验）。约束放在 `domain` 的枚举里，
   编译器能穷尽检查，效果更强。

## 二、物品编码

### 2.1 规则

```text
<类别>:<名字>
```

- 全小写、ASCII、`snake_case`；类别只有 `resource` 和 `equipment` 两种。
- 前缀的意义是**防止不同类别的名字撞车**（比如以后真有 `equipment:food`——军粮）。
- 中文名只用于显示，不参与任何比较。

### 2.2 资源

| 编码 | 中文 | v1 用途 |
|---|---|---|
| `resource:food` | 生活资料 | 生产产出、兑换世界货币；修建也吃它（💡 见 design 4.1） |
| `resource:money` | 世界货币 | 兑换产物；军事生产的消耗比例待定 |

> 原版还有钢铁、石油、铁矿石。**v1 不加**：我们还没有"生产力"这个量，
> 也没有任何规则消耗钢铁，加了就是"以后可能有用"。
> 等真需要时按"只增不改"追加即可。

### 2.3 装备

| 编码 | 中文 | 每件所需兵员 | 用在哪个规则 |
|---|---|---|---|
| `equipment:bomber` | 轰炸机 | 10 | 空袭（打联军军队） |
| `equipment:fighter` | 战斗机 | 5 | 反空袭：只有**巡逻中**的才算 |
| `equipment:transport` | 运输机 | 5 | 掠夺装载上限，且占兵员 |
| `equipment:artillery` | 重炮 | 10 | 炮击；守方反击（私军打光后可由联军军队操作） |
| `equipment:aa_ammo` | 防空弹药 | 0 | 反空袭，消耗品 |
| `equipment:sam` | 地对空导弹 | 10 | 地区防空阵地，反空袭 |

"每件所需兵员"就是设计文档 3.2 的出击闸门：
`实际可用 = min(装备库存, 私人军队 / 每件所需兵员)`。

> 兵员数是**占位值**，只用来把结构跑通，等数值平衡时统一调（改常量，不改编码）。

> 防空弹药归在 `equipment` 下而不是单开 `ammo` 类别：v1 只有这一种消耗品，
> 多一个类别只为一种物品服务不值得。它的"每件所需兵员 = 0"已经说明了它是消耗品。

### 2.4 这些**不是**物品，别塞进库存

`工人`、`私军`、`科技`、`稳定度`、`工资`、`联军军队`、`驻军` 都是**表上的列**，
不是 `库存` 里的行。原因：它们有专属的语义和约束（工人+私军=总人口、驻军与控制方等价），
放进通用库存就把这些不变量弄丢了。

`生产力` 在 v1 也不存在——它是原版的"每小时产能"，v1 的产出直接由工人和科技计算。

`地区建筑.建筑` 直接存编码（不加前缀，建筑只有一类）。

| 编码 | 中文 | 阈值 | 状态 |
|---|---|---|---|
| `school` | 学校 | 60% | 候选，效果：人口恢复（城市招募工人） |
| `warehouse` | 仓库 | 待定 | 候选，效果：地区仓库容量 |

## 六、联军职务

`玩家.联军职务`：

| 编码 | 中文 | v1 权限 |
|---|---|---|
| `leader` | 元首 | 全部（建联军时自动成为） |
| `officer` | 军官 | 预留，v1 与 `member` 同权 |
| `member` | 成员 | 驻军需要联军 + 权限 |

> `玩家.联军_id IS NULL` 时这个字段没有意义（默认 `member`），读取时忽略。

## 七、代码侧怎么用

```rust
// domain：编码的唯一真相
pub enum 物品 {
    资源(资源),
    装备(装备),
}

impl 物品 {
    pub const fn 编码(&self) -> &'static str { … }
    pub fn 解析(s: &str) -> Option<Self> { … }
}
```

- `domain` 里**只有枚举，没有 `String`**：规则函数收到 `物品` 就能穷尽 `match`。
- `storage` 里 `TryFrom<&str>`：读出来解析失败 = 数据损坏，走内部错误，不要猜。
- `server` 渲染时用中文名，写库时用编码，两者只在 `文案` 模块的输入参数里相遇。

## 八、改这一页的规则

| 操作 | 怎么做 |
|---|---|
| 加一种物品 | 追加一行 + `domain` 加一个变体；**不改旧编码** |
| 加一种建筑 | 同上，`建筑` 列不需要迁移 |
| 改中文显示名 | 随便改，只影响 `文案` |
| 改编码 | **禁止**。真要做，得写数据迁移脚本把历史行一起改 |
| 删一种物品 | 标记"废弃"，保留映射；`TryFrom` 仍然认它，规则里当透明处理 |
