## 一、一句话

玩家在聊天群里用文字指令经营工业、组建联军、生产军备，靠私人军队操作这些兵器去轰炸对手，把别人的资源搬回联军的地区仓库。

## 二、世界模型

### 2.1 实体

| 实体 | 是什么 | 关键属性 |
|---|---|---|
| **玩家** | 跨平台身份 | 资源、工人、科技、**私人军队（兵员，整数）**、**装备库存**、出生保护、`Option<联军>` |
| **联军** | 玩家组织，**可以没有** | **联军军队**、地区配额、成员、权限 |
| **地区** | 频道组 + 资源容器 | UID、绑定的频道、地区仓库、**驻军**、**建筑（完成度）**、控制方（联军） |
| **平台绑定** | 平台身份 → 玩家 | `(平台, 平台 uid) → 玩家`，一个玩家 1..N 个，每个平台最多一个 |
| **地区频道绑定** | 频道 → 地区 | `(平台, 频道 id) → 地区` |

✅ **地区没有地理属性**：没有坐标、没有地形、没有距离、没有邻接。所有地区在空间上是同一个点，彼此唯一的区别是 UID 和它绑定的频道。

✅ **一个地区可以绑定多个频道**，且跨平台：同一个地区可以同时是某个 QQ 群、某个 Discord 频道、某个 TG 群。这让不同平台的玩家处在"同一个地方"。

✅ **地区与玩家是弱引用**：玩家驻扎在某地区，只是持有一个 `Option<地区 UID>`。地区易主或被攻陷，玩家本身不受影响。

✅ **玩家刚注册时没有联军**，只有私人军队，因此极度脆弱：炮击把他的私人军队打光，就满足掠夺条件了。新玩家的安全由**出生保护**兜底（见 3.5）。

✅ **一个玩家可以有多个平台身份**：QQ 号、Discord 账号、TG 号可以挂到同一个玩家上，资源、联军、被打的目标都是同一份。绑定只能挂"还没有玩家"的账号——**不做账号合并**，所以不存在"两份资源相加"的规则（D23）。

✅ 没有联军时，`联军军队` 视为 0：空袭对他没有可炸的目标，战争退化为「炮击 → 掠夺」两段式。

### 2.2 编号是秘密

✅ 有两套编号，都是**随机 6 位数字**，只是前缀不同：

| 编号 | 显示 | 指向 | 用途 |
|---|---|---|---|
| 玩家 uid | `P123456` | 一个玩家 | 跨群找到这个人（同群可以直接 `@`） |
| 地区 uid | `R123456` | 一个地区 | 打这个地区 |

✅ **不知道编号，就找不到目标**（跨群时）或打不到地区。编号是"门牌号 + 密码"。

这条规则衍生出几个必须遵守的约束：

1. **别人的编号不能出现在任何公开可见的地方**：不能出现在查询结果里、不能出现在错误提示里、
   不能出现在日志里被随手转发出去。自己的编号可以在 `我的资料` 里看到。
2. **地区仓库比玩家身上安全**：打地区必须先拿到 `R…`；打玩家，同群可以 `@`，
   跨群才需要 `P…`。这是"把物资放地区仓库"的收益来源。
3. **编号是弱秘密**：6 位数字只有 90 万个组合（`100000`–`999999`），理论上可以枚举。
   所以攻击必须有成本门槛——**枚举是"贵"，不是"不可能"**。
4. **编号不从自增 id 推导**：`P37` 既暴露"我是第 37 个注册的"，又方便枚举，那就不叫凭证了。

💡 **提高枚举成本的具体机制**：每次对地区发起攻击（无论 UID 是否存在）都消耗**军事行动点**，且失败不退款。军事行动点缓慢自然恢复。这样枚举 100 万次需要天文数字的时间，而正常玩家打一次目标只花得起一次。

### 2.3 地区不会消失，只会易主

✅ 地区**不能被删除**。频道解绑、机器人退群，地区依然存在（只是暂时没有入口）。

✅ 地区**可以被攻击、被攻陷**，攻陷后控制方变更。

✅ **地区的控制方只能是联军，不能是个人**（因为只有联军能驻军，见 3.1）。

❓ **攻陷之后，地区仓库里的物资归谁？** 三种可能：
- (a) 原封不动留在地区，新控制方直接享有；
- (b) 一部分被攻方掠走，剩余留存；
- (c) 全部销毁。

### 2.4 联军的地区配额

✅ 一个联军能控制的地区数量，由**成员数量**决定。人多 → 地多 → 仓库多 → 更安全，这是联军的成长曲线。

❓ 需要确定：
- **配额公式**：几人一个区？（例：1 + 成员数 / 3？）
- **超配额怎么办**：成员退出导致配额下降时，多出来的地区怎么处理——自动放弃最弱的？还是锁定不能再占领新地区？
- **配额是"持有上限"还是"同时占领上限"**？

## 三、战争

### 3.1 三种兵力，三个独立的池子

✅ 战争里**没有建制、没有部队编成、没有单位**。兵力是整数，武器是库存数量。

| 名称 | 归属 | 存在哪张表 | 被什么打 | 作用 |
|---|---|---|---|---|
| **私人军队** | 玩家 | `玩家` | 炮击 | **操作玩家装备的兵员**；也是玩家最软的地方 |
| **联军军队** | 联军 | `联军` | 空袭 | 联军的共享兵员；**转化为驻军的来源**；**能操作玩家名下的重炮反击** |
| **驻军** | 地区 | `地区` | 攻陷 | 防守地区；**能操作地区里的重炮反击** |

✅ **三个池子独立存储**，各自挂在自己的表上，不是"同一种兵换个地方放"。

✅ **驻军不是"把私军调过去"，而是从联军军队转化**：只有联军成员、且拥有相应权限的人，才能执行驻军。

✅ **没有联军的玩家不能驻军**，因此不能守地区。

❓ **转化的方向是单向的吗**？驻军能不能撤回成联军军队？（原版有"撤回驻军"。）

### 3.2 装备与兵员

✅ **装备由玩家生产，挂在玩家名下**（库存）。

✅ **私人军队是一个整数**，挂在 `玩家` 上，不做逐件编制表。

✅ **使用战争兵器靠私人军队**——私军不是单纯的血量，它是**操作兵器的兵员**。

这条是整套战争模型的枢纽。推论：

- 装备再多，私军不够也打不出伤害。**私军是战斗力的闸门。**
- 炮击打光私军 = 解除对方的武装（装备还在，但没人操作）。
- 所以"造装备"和"招兵"必须平衡，不能只堆一种。

✅ **出击数量公式**：`实际可用 = min(装备库存, 私人军队 / 每件所需兵员)`。

每种装备只需要一个"每件所需兵员"常量（见 [catalog.md 2.3](./catalog.md#23-装备12-种)），不需要逐件分配。
例：战斗机每架需 5 兵员，你有 50 架、私军 200 → 只能起飞 40 架。

💡 这个方案的副作用我挺喜欢：**掠夺也要占兵员**（运输机得有人开），所以你不能一边把飞机全派出去、一边还想去抢东西。战争里自然长出取舍。

❓ **联军军队能操作哪些兵器？** 目前只确认它能操作地区的重炮（3.3 反击情形二）。这是一个受限于"驻军 + 地区重炮"的窄口径，还是一个通用的第二操作池？

### 3.3 攻击流程

✅ 顺序固定，不能跳步。但**段数取决于目标有没有联军**。

**目标有联军 → 三段：**

```
① 空袭  → 打光对方【联军军队】
② 炮击  → 打光对方成员的【私人军队】
③ 掠夺  → 用运输机把对方资源搬走
```

**目标没有联军 → 两段：**

```
① 炮击  → 打光他的【私人军队】
② 掠夺  → 用运输机把对方资源搬走
```

#### 空袭：强者/先手者零成本获胜

✅ 空袭对攻方**零损耗**：兵员不掉，只消耗弹药；唯一的损失来自守方防空击落的飞机。

✅ 这就是"谁飞机多、谁先动手，谁就白赢"的机制——空袭不是消耗战，是碾压。

✅ 所以空袭唯一的平衡手段是守方的防空（见 3.4）。

#### 炮击：一次交换，不是循环

✅ 攻方开火 → 守方若能反击则反击一次 → **结束，不会再有第三轮**。

✅ 守方**能反击**的两种情形：

1. 攻方第一轮炮击后，守方的**重炮与私军都还剩很多**；
2. 守方的**私军被打光，但重炮还在，且有足够的联军军队操作这些重炮**。

✅ **反击是跨实体组合**：重炮在**玩家自己的库存**里，操作重炮的联军军队在**联军账上**。只要联军军队数量足够，哪怕这个玩家的私军已经归零，也能用联军军队开炮反击。

💡 这带来一个不太直观的效果：**加入一个大联军，等于给自己名下的重炮配了备用炮手**。联军规模因此不只是"打架人多"，它直接是每个成员的防御加成。

✅ 不满足上述任一条件时，炮击就是单方面碾压，守方无反击。

💡 炮击因此是"消耗战"工具：它有反击，所以强者不能免费赢；空袭与炮击在成本结构上正好互补。

#### 掠夺

✅ **前置条件是"对方的军队全灭"**：有联军时是"联军军队 = 0 且该联军所有成员私人军队 = 0"；没有联军时是"私人军队 = 0"。

✅ 掠夺量受**运输机数量**限制（原版叫"设置掠夺编队"，按大型运输机数量设），且占兵员。

✅ **攻陷地区是另一条线**：打光地区的驻军即可易主，与打玩家的三段式互不依赖。

💡 每一阶段都是"两个整数相减"，非常适合写成纯函数 + 一条条件 UPDATE。不需要战斗模拟、不需要 tick、不需要锁表。

### 3.4 空袭的反制

✅ 防守方只有三种东西能有效保护：

| 反制手段 | 作用 |
|---|---|
| **防空弹药** | 消耗品，拦截来袭飞机 |
| **地对空导弹** | 部署在地区的防空阵地 |
| **正在巡逻的战斗机** | 只有"巡逻中"的才计入，停在机场的不算 |

✅ 其余的兵种、防御工事对空袭**没有减免效果**。

### 3.5 出生保护

✅ 新玩家有一段时间不能被攻击。没有这个，任何人注册后几分钟内就会被抢光。

❓ 需要确定：
- **时长**：现实时间多久？
- **保护范围**：只防玩家，还是也防他驻扎的地区？
- **解除条件**：期满？主动发起第一次攻击？加入联军？
- **🗝 关键**：保护期内**能不能主动攻击别人**。如果能，"开小号 → 在保护期内打人"就成了无解外挂。建议保护期内禁止主动攻击，且一旦加入联军立即解除保护。

## 四、经济（v1 沿用原版最小闭环）

✅ v1 的经济沿用《马列机器人》的核心循环，不采用《新马列文游策划》里的人口/劳动力/建筑位模型（那套属于 v3）。

```
签到 → 招募工人 → 设置工资 → 生产（生活资料）
     → 兑换世界货币 → 提升科技 → 军事生产 → 军备
```

✅ **私军由玩家从工人扩充而来**：工人和私军是同一批人口，扩军就是把工人转成兵。

✅ **生产要消耗"生产次数"**：每小时 +1，最多攒 **8** 次；没有次数就不能生产。
这是一根"上线频率"的杠杆——攒满 8 次还不来生产，就是纯亏；但也不逼你每小时守着。

✅ **这两个数字由全服定时任务推进**：每小时给所有 `生产次数 < 8` 的人 +1，
每天 0 点把所有人的 `今日招募数量` 清零。不按人存"上次结算时间"——
进度记在单行表 `系统状态` 里，进程没跑的那几小时，启动时一条 `LEAST(8, 次数 + N)` 补回来。

✅ **招募按"每日总量"算**：玩家自己选每次招多少（`招募工人 <数量>`），
但每天的总量有上限，0 点清零。所以库里需要 `今日招募数量` 一个计数器——
"上次招募时间"只能告诉你"招过了"，不能告诉你"还能招多少"。

✅ **科技靠科技池**：投入资源填池子，攒满 `科技池容量` 升一级科技。

✅ **地下工厂**：把工人转成 `地下工人` 后，空袭炸不到这批人（❓ 产量系数待定）。
✅ **休假工人**：暂时离岗的工人；投放生物病毒会连他们一起杀（❓ 怎么休假、怎么回来待定）。

这是整个游戏最重要的一根平衡杠杆：

- 工人多 → 产出高、发展快 → 但兵少，挨打
- 兵多 → 能打能守 → 但工人少，产出低
- **私军阵亡 = 人口永久损失**，不只是掉一条血量

✅ 原版还有一条反向机制：`裁军` 会把兵退回工人，但**跑掉四分之一**。这条很值钱——它防止玩家在"扩军 / 裁军"之间无成本地来回横跳。

❓ **换算比例**：1 工人 = 1 私军？扩军要不要额外消耗生活资料或装备？
❓ **人口恢复通道**：私军死光是永久损失。如果玩家没有恢复人口的途径，被打残一次就再也起不来了。原版靠"城市招募工人"（需学校 60%）恢复，v1 需要一条等价通道——否则一次战败 = 删号。

❓ 还需要确定一个"第一天就能打出第一架"的尺度：
- 初始资源与工人数
- 每次生产的产出公式（工人 × 科技 × 稳定性？）
- 工资与稳定度的关系（工资低于基准掉稳定度，低于 0 不能生产）
- 各类军备的造价

❓ **时间模型**：原版是"现实时间"，v2 是"1 小时 = 1 游戏日，0–6 点禁战"。v1 取哪个？

### 4.1 地区建筑

✅ **v1 有建筑，建筑挂在地区上**（不挂玩家、不挂联军）。所以建筑跟着地区易主：
谁控制这个地区，谁用它的建筑。这和"物资放地区仓库更安全"是同一条激励——
把地区当成真正的据点，而不是一个仓库编号。

✅ **一种建筑在一个地区只有一份，进度用 0–100 的完成度表示**，到阈值才解锁效果。
原版就是完成度制：学校建到 60% 才能"城市招募工人"，炼钢厂到 70% 才能炼钢。

✅ 建筑清单是**固定几种**，对齐原版；不采用《新马列文游策划》的建筑位 /
劳动力分配 / 电力那一套（那是 v3）。

❓ **清单未定**。原版的可作候选：学校、仓库、公路、铁路、机场、居民区、剧院、
炼钢厂、港口、生物实验室、艺术中心（见 `.scratch/指南.txt`，不在仓库里）。

❓ 每种建筑需要定：效果、解锁阈值、造价、一次修建推进多少完成度、能不能重复修建。

💡 建议 v1 只留 3–4 种，且每种必须咬住现有闭环的一环，否则就是"以后可能有用"：

| 建筑 | 咬住哪一环 |
|---|---|
| **学校** | **人口恢复通道**——正好补上第四节"一次战败 = 删号"那个缺口（原版是学校 60% 解锁城市招募工人） |
| **仓库** | 地区仓库容量上限，给"把东西放地区"加一道闸 |
| **机场** | 空袭：出击上限 / 被空袭时的防空 |
| **剧院** | 稳定度（原版：100 居民演出一次，恢复稳定度，不消耗居民） |

💡 **修建本身消耗生活资料**，且施工要占工人——这样"盖楼"和"扩军"也在抢同一批人口，
和第四节的杠杆是同一根。

## 五、v1 指令表（草案）

刻意压到最少。每条都能在战争或经济闭环里找到位置，没有一条是"以后可能有用"。

| 分组 | 指令 | 备注 |
|---|---|---|
| 账号 | `注册`、`我的资料`、`我的军队` | 注册是**显式**的：不注册不能玩 |
| 跨平台 | `绑定账户`、`确认绑定 <口令>`、`最终同意` | 三步绑定，见下 |
| 经济 | `签到`、`招募工人 <数量>`、`设置工资`、`生产`、`兑换世界货币`、`提升科技` | `生产` 消耗生产次数 |
| 军事生产 | `军事生产 <装备> <数量>`、`我的军备`、`招募私军 <数量>` | |
| 联军 | `组建联军 <名字>`、`邀请 <玩家>`、`我的联军` | v1 只做最小组建 |

✅ **目标有三种写法**，都能落到同一个玩家：

| 写法 | 例 | 适用 |
|---|---|---|
| @提及 | `@晓` | 同群，Koishi 把 @ 解析成平台用户 id |
| 编号 | `P123456` | 跨群、跨平台 |
| 平台账号 id | `3071303571`（QQ 号） | 知道他绑的社交账号，直接敲 |

打地区只能用 `R123456`——地区没法 `@`，这正是"地区仓库更安全"的原因。

✅ **玩家没有名字**：不存"指挥官名"这一列，用 `P123456` 这个编号称呼。
同群直接 `@某人`（Koishi 把 @ 解析成平台用户 id，见协议 `mentions`），
跨群用 `P…` 编号，或者直接敲他绑的社交账号 id（QQ 号）。
三种写法都先落到"某个玩家"，再算规则。
| 排行 | `贡献排名` | |

✅ **注册是显式的**：`注册` → 建玩家 + 写第一条平台绑定。没注册时发其他指令回 `not_registered`，
提示"先发 `注册`"。**不能自动注册**——自动注册会让每个平台账号都变成玩家，
"这个账号还没注册"这个前提就永远不成立，跨平台绑定无从发起。

跨平台绑定三步（流程取自 v2，补了第三步的"确认前先显示对方"）：

1. 在 A 平台发 `绑定账户` → 拿到 6 位口令，5 分钟有效；同一玩家再发会作废旧口令
2. 到 B 平台发 `确认绑定 <口令>` → 检查 B 是否已经有玩家，有就拒绝（**绑定不是合并**）
3. 回 A 平台发 `最终同意` → 显示对方 `平台 / uid / 昵称`，确认后落库

口令存在 `server` 内存里：它在 5 分钟内本来就该过期，重启丢掉不产生任何数据不一致，
让玩家重发即可。换成库表要多处理过期清理与并发确认，收益是"跨实例"，v1 不需要（D23）。

> 登录路径：每条 `command` 带 `(平台, userId)`，先查 `平台绑定` 得到 `玩家_id`，
> 查不到就是"未注册"。这是每条消息的固定第一步，走 `(平台, 平台_uid)` 唯一索引。

❓ 指令的**分词规则**未定：原版要求所有指令带句号（`签到。`），是服务器特有的解析怪癖。建议 v1 不强求句号，但容忍它。
