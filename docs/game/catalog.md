# 键表：落库的稳定编码

>
> 相关：[data-model.md](../arch/data-model.md)、[decisions.md D25 / D27 / D36](../../decisions.md)

## 一、这一页解决什么

库里有一批 `TEXT` 列，值的含义完全靠约定：`库存.物品`、`地区建筑.建筑`、
`库存.所有者类型`、`平台绑定.平台`、`玩家.联军职务`、`联军.政治体制`。

**这些值是稳定键，不是显示名。** 一旦写进库就不许改——改一次就要动全部历史数据。
所以先把词表定死，之后写代码、写迁移、跟 Koishi 插件对齐都照这一页来。

三条规则：

1. **编码只增不改。** 要改名只改中文显示名，编码不动。
2. **废弃用标记，不删行。** 老数据里可能还有这个编码，删了会让 `TryFrom` 变成"数据损坏"。
3. **不在数据库里加 CHECK 约束。** 加一种物品只需改代码；写成 CHECK 的话，
   每次加物品都要一次 `ALTER TABLE`（还要全表校验）。约束放在 `domain` 的枚举里，
   编译器能穷尽检查，效果更强。

> **收录范围 = 原版指南《马列机器人新手指南》2.1.11 里出现的全部物品，加上 v2 `Player`
> 类型里多出来的资源（铝/铀/钚）。** 键先全定下来，规则可以后接：清单是超集，
> `domain` 里先实现多少条规则是另一回事（D27/D28）。覆盖度逐条对账见 2.6。

## 二、物品

### 2.1 编码规则

```text
<类别>:<名字>
```

- 全小写、ASCII、`snake_case`；类别三个：`resource` / `equipment` / `ammo`。
- 前缀的意义是**防止不同类别撞车**：`rocket` 是火箭炮（装备）还是火箭弹（弹药）？靠前缀分开。
- 中文名只用于显示，不参与任何比较。

三个类别的分界：

| 类别 | 是什么 | 判据 |
|---|---|---|
| `resource` | 经济物资 | 生产/开采/兑换得到，不直接参与战斗 |
| `equipment` | **耐久的**战斗器械 | 要兵员操作，打完还在 |
| `ammo` | **一次性**战斗消耗品 | 用掉就没 |

### 2.5 这些**不是**物品，别塞进库存

| 名字 | 是什么 | 在哪 |
|---|---|---|
| `工人`、`私军` | 人口 | `玩家` 的列（工人 + 私军 = 总人口） |
| `科技` | 等级 | `玩家` 的列 |
| `稳定度`、`工资` | 状态/参数 | `玩家` 的列 |
| `生产力` | **计算值**，不是存量 | 由工人 × 科技 × 稳定度算出，不落库 |
| `军事行动点` | 行动资源 | 原版可消耗生活资料增加；v1 要不要自然恢复未定 |
| `联军军队`、`驻军` | 共享/驻防兵员 | `联军` / `地区` 的列 |
| `居民`、`艺术家` | 人口分组 | 居民区/艺术中心的产物，v1 还没接 |
| `悬赏` | 一条记录（谁悬赏谁多少钱） | 不是库存；v1 没做 |
| `贡献` | 玩家对联军/全局的贡献值 | 玩家列（`贡献排名` 要用；v1 表里还没有，见 data-model 8.2） |
| `海洋垃圾` | 地区污染计数 | 运河/港口的脏数据，不是物品 |

判据：**能堆在仓库里、数量可以相加减的，才是物品**；有专属语义和不变量的，是列。

## 四、编号（uid）

编号不是物品，但同样是"落库的稳定值"，一起管。

| 编号 | 前缀 | 显示 | 落库 | 是什么 | 保密 |
|---|---|---|---|---|---|
| 玩家 uid | `P` | `P123456` | `INT`，6 位 | 跨群找到这个人的**秘密凭证** | 是 |
| 地区 uid | `R` | `R123456` | `INT`，6 位 | 打这个地区的**秘密凭证** | 是 |
| 联军 uid | `C` | `C123456` | `INT`，6 位 | 查这个联军的**公开门牌** | 否 |

四条规则：

1. **随机 6 位，不从自增 id 推导。** `P37` 这种编号既暴露"我是第 37 个注册的"，
   又方便枚举——那就不是凭证了。
   唯一性由数据库的 `UNIQUE` 约束兜底：生成时撞了就重试（90 万个号，2 人规模撞不到）。
   玩家、地区、联军都**永不删除**（地区只易主；联军只解散留标记，见
   [design.md 待定 13](./design.md#六待定清单)），所以编号不会被回收再发出去。
2. **前缀只在显示与解析时加，落库只存数字。** `玩家` 表里的 uid 天然属于玩家，
   不需要再存一个 `P`；命令里必须带前缀，解析器据此判断"找玩家、找地区还是找联军"。
3. **三个前缀是三个独立命名空间**：`P123456`、`R123456`、`C123456` 可以同时存在。
4. **`P` 与 `R` 不得出现在别人能看到的输出里**（排行榜、战报、错误提示）；只给本人看
   （`我的资料` 里显示自己的 `P…`）。它们是凭证，泄露等于把钥匙贴出去。
   **`C` 没有这个限制**：知道 `C123456` 既找不到人、也打不了地区，它只是一个门牌——
   排名、战报、`我的联军` 里都可以出现。

> 和 `id` 的分工：`id` 是内部主键（join、索引、日志），`uid` 是对外凭证（玩家输入）。
> 两者绝不能互相替代——拿 uid 当主键，换一次凭证就要改所有引用行（D30）。

## 八、代码侧怎么用

```rust
// domain：编码的唯一真相
pub enum 物品 {
    资源(资源),
    装备(装备),
    弹药(弹药),
}

impl 物品 {
    pub const fn 编码(&self) -> &'static str;
    pub fn 解析(s: &str) -> Option<Self>;
}
```

- `domain` 里**只有枚举，没有 `String`**：规则函数收到 `物品` 就能穷尽 `match`。
- `storage` 里 `TryFrom<&str>`：读出来解析失败 = 数据损坏，走内部错误，不要猜。
- `server` 渲染时用中文名，写库时用编码，两者只在 `文案` 模块的输入参数里相遇。

## 九、改这一页的规则

| 操作 | 怎么做 |
|---|---|
| 加一种物品 | 追加一行 + `domain` 加一个变体；**不改旧编码** |
| 加一种建筑 | 同上，`建筑` 列不需要迁移 |
| 改中文显示名 | 随便改，只影响 `文案` |
| 改编码 | **禁止**。真要做，得写数据迁移脚本把历史行一起改 |
| 删一种物品 | 标记"废弃"，保留映射；`TryFrom` 仍然认它，规则里当透明处理 |
