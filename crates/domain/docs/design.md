## 一、这个 crate 是什么

所有游戏规则的**纯计算**。零依赖、零 IO、零 async。

它存在的唯一目的：让"签到该给多少资源""炮击该扣多少兵"这类问题，
可以脱离数据库和网络被单独验证。

## 二、函数的统一形状

```rust
pub fn 结算(旧状态: &玩家状态, 输入: 输入, 现在: 时间) -> Result<结算结果, 错误>
```

三条硬要求：

1. **时间是参数，不是 `SystemTime::now()`。**
   任何"现在几点了"的读取都在 `server` 里做完，传进来。
   否则这个函数就没法测"跨天签到""保护期到期"这类逻辑。
2. **随机数是参数或由 `server` 传入的种子。**
   `domain` 里不出现 `rand`。
3. **返回"新状态 + 事件列表"，不返回文案。**
   事件是结构化的（`事件::签到获得 { 生活资料: 1200 }`），
   转成人话是 `server` 里 `文案` 模块的事。

## 三、数值约定

- 全部整数：`i64`（需要中间量时用 `i128` 再收敛）。
- 禁止浮点：`clippy::cast_precision_loss` 等三条是 deny，且浮点会带来"1.0000001 个兵"这种问题。
- 单位约定（草案，待 `design.md` 定稿后同步）：
  - 生活资料、世界货币：以 **1** 为最小单位
  - 工人、私军：以 **1 人**为最小单位
  - 装备：以 **1 件**为最小单位
- 所有减法走 `checked_*` / `saturating_*`，`arithmetic_side_effects` 已开 warn。

## 四、错误

- 用 `thiserror` 定义本 crate 的错误枚举。
- 错误里**不带玩家可见文案**。错误只表达"发生了什么"，表达"怎么跟玩家说"是 `server` 的事。
- 典型错误：`资源不足 { 需要: i64, 现有: i64 }`、`未注册`、`保护期内`。

## 五、模块划分（草案）

```
src/
├── lib.rs
├── 玩家.rs      工人 / 私军 / 资源 / 保护期
├── 经济.rs      签到 / 生产 / 工资 / 稳定度
├── 军备.rs      生产装备、兵员闸门
├── 战争.rs      空袭 / 炮击 / 掠夺
├── 地区.rs      驻军、攻陷
└── 建筑.rs      修建、完成度阈值
```

按业务拆，不按技术拆。一个模块一个 `#[cfg(test)] mod tests`。

## 六、测试策略

规则的每一个分支都要有一条测试，且测试里不出现数据库、不出现字符串比较（比较结构化事件）。

```rust
#[test]
fn 炮击时对方无兵可反击() {
    let r = 战争::炮击(&攻方, &守方, 现在).unwrap();
    assert!(r.守方私军 == 0);
    assert!(r.事件.iter().any(|e| matches!(e, 事件::无反击)));
}
```
