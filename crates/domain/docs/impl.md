# domain — 纯规则层

>
> **类型定义的唯一事实来源**见 [docs/arch/data-model.md](../../../docs/arch/data-model.md)。
> 全局规则见 [design.md](../../../docs/game/design.md)；分层理由见 [arch/overview.md](../../../docs/arch/overview.md)。

## 一、这个 crate 是什么

所有游戏规则的**纯计算**。零依赖、零 IO、零 async。

它存在的唯一目的：让"签到该给多少资源""炮击该扣多少兵"这类问题，
可以脱离数据库和网络被单独验证。

## 二、函数的统一形状

```rust
pub fn 结算(旧状态: &玩家状态, 输入: 输入, 现在: 时间) -> Result<结算结果, 错误>
```

三条硬要求：

1. **时间是参数，不是 `SystemTime::now()`。**
   任何"现在几点了"的读取都在 `server` 里做完，传进来。
   否则这个函数就没法测"跨天签到""保护期到期"这类逻辑。
2. **随机数是参数或由 `server` 传入的种子。**
   `domain` 里不出现 `rand`（编号的候选产生也在 `server`，见 decisions.md D44）。
3. **返回"新状态 + 事件列表"，不返回文案。**
   事件是结构化的（`事件::签到获得 { 生活资料: 1200 }`），
   转成人话是 `server` 里 `文案` 模块的事。

## 三、数值约定

- 全部整数：`i64`（需要中间量时用 `i128` 再收敛）。
- 禁止浮点：`clippy::cast_precision_loss` 等三条是 deny，且浮点会带来"1.0000001 个兵"这种问题。
- 单位约定（草案，待 `design.md` 定稿后同步）：
  - 生活资料、世界货币：以 **1** 为最小单位
  - 工人、私军：以 **1 人**为最小单位
  - 装备：以 **1 件**为最小单位
- 所有减法走 `checked_*` / `saturating_*`，`arithmetic_side_effects` 已开 warn。

## 四、错误

- `domain` **零依赖**，所以错误不用 `thiserror`，`Display` / `Error` 手写（`src/error.rs`）。
- 错误里**不带玩家可见文案**。错误只表达"发生了什么"，表达"怎么跟玩家说"是 `server` 的事。
- 已有变体：`未注册`、`频道无地区`、`物资不足`、`数量溢出`——最后两个由
  `库存::增` 的不变量拒绝产生（减成负数 / 加法溢出，宁拒绝不饱和）。

## 五、模块划分

```
src/
├── lib.rs        模块接线 + 平台 re-export
├── uid.rs        编号：前缀 / 区间 / 显示 / 重试上限（规则侧，D44）
├── model.rs      实体与词表：newtype、玩家/联军/地区/库存/地区建筑、
│                 物品（资源 14 + 装备 12 + 弹药 6）、平台/职务/政体/权限等级
├── command.rs    领域指令枚举（路由 match 它，不 match 字符串）
└── error.rs      领域规则拒绝
```

已落地的模块按"技术形状"分（实体 / 词表 / 指令 / 错误）；
**规则函数**按业务拆，等 S3+ 实现时再加（`经济.rs`、`战争.rs`…），
一个模块一个 `#[cfg(test)] mod 测试`。

词表的 `编码` / `解析` / `全部` 由 `model.rs` 里的 `编码枚举!` 宏从**同一张配对表**生成，
两个方向不可能漂移；对账数量（14 / 12 / 6）钉死在测试里。

## 六、测试策略

规则的每一个分支都要有一条测试，且测试里不出现数据库、不出现字符串比较（比较结构化事件）。

```rust
#[test]
fn 炮击时对方无兵可反击() {
    let r = 战争::炮击(&攻方, &守方, 现在).unwrap();
    assert!(r.守方私军 == 0);
    assert!(r.事件.iter().any(|e| matches!(e, 事件::无反击)));
}
```

词表另有硬性测试：每个枚举 `解析(编码(x)) == x` 全量往返 + 未知编码返回 `None`。
