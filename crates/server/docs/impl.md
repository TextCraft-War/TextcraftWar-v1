# server — WebSocket 服务器

>
> 契约见 [docs/protocol.md](../../../docs/arch/protocol.md)；分层见 [architecture.md](../../../docs/arch/overview.md)。

## 一、这个 crate 是什么

命令外壳。它做四件事：

1. 收 WS 消息，解 JSON
2. 把文本解析成指令
3. 调 `domain` 算规则，调 `storage` 落库（**开事务**）
4. 把结果渲染成玩家可见文本，发回去

它**不写规则**，也**不写 SQL**——`sqlx` 根本不在本 crate 的依赖里，
事务句柄是 `storage` 给的不透明值（D40），想在这层写 SQL 会直接编译失败。

拆成 **lib + bin**：`src/lib.rs` 公开 `状态` / `路由` / `初始化日志` / `处理` / `来信` / `错误`；
`src/main.rs` 只剩"读配置、建池、跑迁移、监听"的启动脚本。
拆分的直接动机是**集成测试**：测试要绕过 WebSocket 直接调 `处理`，二进制 target 给不了这个入口。

模块（文件名英文、模块名中文，靠 `#[path]` 转接——rustc 拒绝非 ASCII 文件名）：

| 模块 | 文件 | 职责 |
|---|---|---|
| `连接` | `ws.rs` | 帧循环：读、写、Ping/Pong、关闭、回执发送 |
| `会话` | `session.rs` | 握手状态机（5s/token/版本）+ 平台一致与长度门卫 |
| `解析` | `parser.rs` | 玩家原话 → `domain::指令`（认不出的原文留在本层） |
| `分发` | `dispatch.rs` | 身份先行 + 读写分流（D46）+ 时间注入 |
| `处理器` | `handlers/` | 每类指令的业务流程（现在只有 `账号`） |
| `调度` | `scheduler.rs` | 后台心跳：60 秒巡检 `系统状态`（S4 填补算） |
| `文案` | `text.rs` | 玩家可见文本的唯一出口 |
| `错误类型` | `error.rs` | 分层错误（D48）+ 三张表 |
| `时钟` | `clock.rs` | 唯一取当前时间的地方（处理器收注入的时间） |

> 模块名 `错误类型` 不是口误：**模块与类型在同一个命名空间**，模块若也叫 `错误`，
> 把里面的 `错误` 提到根上就 E0255。文件名同理——中文模块名配英文文件名是
> rustc 的硬约束（`error[E0754]`），不是品味问题。
> `handlers/account.rs` 这类子模块的 `#[path]` 相对**所在目录**解析，规则与顶层一致。

## 二、启动序列

```
读配置（环境变量）
  → 建连接池
  → storage::迁移                    建表 / 升级表
  → server::启动调度器               后台心跳与监听并行
  → axum::serve(监听地址, 路由)
```

顺序是有意义的：**迁移在绑定端口之前**。库连不上或迁移失败就直接启动失败，
不要出现"端口开着但所有指令都报错"的半死状态。
（`domain` 的数值常量编译进代码，没有运行时"定义表"要加载——见 decisions.md D16/D17。）

环境变量、PG 准备与种子数据是**操作域**，唯一出处：
[guides/deployment.md](../../../docs/guides/deployment.md)，这里不重复抄表。

## 三、连接处理

一条连接一个 `tokio::spawn` 任务，内部是读循环。**两层**（D48 拆分）：

- `连接`（`ws.rs`）只管**帧**：读、写、Ping/Pong、关闭帧、回执发送；
- `会话`（`session.rs`）管**状态机**：握手（5s 超时 → 解 JSON → 必须是 hello →
  token → 版本 → 平台 → 回 ready）与每条指令的门卫（512 字符上限、
  平台编码合法、平台与握手一致）。

```
accept 升级
  → 等待 hello（超时 5s）
  → 校验 token + 版本
  → 回 ready
  → loop { 读一帧 → 门卫 → 分发 → 写回 }
```

- 连接上**不保存游戏状态**。每条 `command` 自带 `platform` / `channelId` / `userId`，
  处理逻辑完全无状态，任何一条连接都能处理任何一条消息。
- 连接只记一样东西：**握手时的平台**。每条 `command` 的 `platform` 必须与它一致，
  否则回 `bad_request`——协议里"一条连接 = 一个平台"是校验，不是注释。
- JSON 坏了**不再断连**：回一条 `error` 继续跑。断连只留给传输层故障。
- 文本超 **512 字符**（字符数，不是字节数）直接拒绝，**不截断**——
  截断会让玩家以为自己发对了。
- 写回时用同一条连接；`channelId` 原样带回，由 Koishi 负责路由到具体群。

## 四、命令分发

### 4.1 文本解析（v1 规则）

```
"注册"          → 解析::结果::指令(domain::指令::注册)
"随便说说"      → 解析::结果::不认识 { 原文: "随便说说" }
```

解析产出 [`domain::指令`](../../domain/docs/impl.md)（D44/D48）：一条指令
**意味着什么动作**是规则层的事，路由 `match` 的是它，不是字符串；
认不出的原文不是领域概念，留在 `解析::结果::不认识`，由分发层结合身份
决定对外错误码（`not_registered` / `unknown_command`）。

规则：

1. 去掉首尾空白；**剥掉句末标点**（`。` `.` `！` `!`，兼容原版的 `签到。` 习惯，但不强制）。
2. 按空白切分，第一段是指令名，其余是参数。零参指令目前**忽略**多余参数
   （`注册 晓` 也是 `注册`）；等有了带参指令再让解析返回参数列表。
3. 指令名匹配用**精确匹配**，不做前缀匹配（避免 `生产` 和 `生产次数` 打架）。
4. 不在任何地方做权限判断——权限属于 `domain`（如"非联军成员不能驻军"）。

### 4.2 路由表

**两级**（D49 身份前置）：外层 `match` 只分"注册 / 其余 / 不认识"——
`注册` 是唯一走在身份门之前的指令（没注册的人才需要它）；其余一切指令
（含不认识的词头）先过身份门，过了门的进 [`分发已注册`] 的内层 `match`。
不引入 trait 注册表；指令多了按 D49 触发线再拆。

```
解析::结果::指令(注册)     → 处理器::账号::注册(...)   自己处理"已注册"：幂等回编号，不报错
解析::结果::指令(其余)     → 身份门（查绑定，查不到 → error { not_registered }）
                             → 分发已注册：
                                 我的资料 → 处理器::账号::我的资料(...)  纯读
                                 签到     → 经济::签到(...)              （S4）
                                 炮击     → 战争::炮击(...)              （S6）
解析::结果::不认识 { 原文 } → 身份门（查不到 → error { not_registered }）
                             → error { unknown_command }
```

**身份门写在管线上，不写在分支里**（D49）：拦截只出现一次，
往后加指令的分支**想漏都漏不掉**；`分发已注册` 拿到的绑定必然存在，
分支只管业务。**未知指令也先过身份门**是刻意的：对没注册的人，
"你发的是什么"不重要，"先注册"才重要；对已注册的人，才值得告诉他"这条没看懂"。

[`分发已注册`]: ../src/dispatch.rs

### 4.3 身份与绑定口令

**每条消息的第一步是解析身份**，而不是解析指令：

```
(平台, userId) --查 平台绑定--> 玩家_id
```

查不到就是"未注册"：只有 `注册` 能继续，其它指令一律回 `not_registered`，
文案提示"先发 `注册`"。**不做自动注册**——自动注册会把每个平台账号都变成玩家，
跨平台绑定就没法发起了（D23）。

`注册` 在一个事务里按固定顺序做四步（D41 / D42）：

1. **串行化**：`pg_advisory_xact_lock(平台:账号)`。两个并发的 `注册` 不会各建一个玩家，
   第二个等第一个提交后查到绑定，直接回"已经注册过"（D42）。
2. **幂等查绑定**：已注册就回编号，**不报错**——协议不做传输层去重，靠业务幂等。
3. **查频道地区**：频道没绑地区回 `no_region`，**不建玩家**。出生地区 =
   注册所在频道所属地区（D41）——频道 = 地区是 v1 的空间模型（D6），
   注册信息里唯一稳定的"你在哪"就是所在频道。
4. **建玩家 + 写绑定**：编号在 `server` 随机生成（合法区间与重试上限是规则，
   在 `domain::编号`——D44；怎么抽是策略，`rand` 区间抽样在这里），
   `storage::插入玩家` 用 `ON CONFLICT (uid) DO NOTHING` 只回答"这个号被占了吗"；
   绑定**不带**冲突兜底——锁保证撞不上，真撞了就是程序错误，让它炸出来。

日志里**不许出现 `P…` 编号**：它是秘密凭证（D30），新玩家注册只记 `玩家_id` 与地区名。
回执里则**必须**显示编号：那是玩家拿到自己凭证的唯一入口。

跨平台绑定是个**短命状态机**，状态只活在内存里：

```rust
struct 待绑定 {
    玩家_id: i64,
    目标平台: Option<String>,   // 对方输码后才填
    目标_uid: Option<String>,
    过期时间: 时间戳,
    失败次数: u8,
}

// 口令 → 待绑定。整个 server 一份。
口令池: Mutex<HashMap<String, 待绑定>>
```

- **生成**（`绑定账户`）：6 位随机数字，5 分钟有效；同一玩家已有的待绑定先删掉
  ——同时只允许一个在飞，否则"我到底在确认哪一个"没有答案。
- **确认**（`确认绑定 <口令>`）：口令存在、没过期、失败次数 < 3；再查该平台账号是否
  已经有玩家，有就拒绝（**绑定不是合并**）；通过后把 `(平台, uid)` 记进这条口令。
- **完成**（`最终同意`）：要求发起者就是口令所属玩家、目标已填；**先把对方身份显示出来**
  （平台 / uid / 昵称），玩家确认后才落库。不显示的话，这一步等于盲签。
- **过期**：不依赖定时器（进程被杀不会漏一条永远有效的口令），每次校验时比对
  `过期时间`；生成新口令时顺手扫一遍清掉过期的。

为什么放内存：它的生命周期只有 5 分钟，丢了不产生任何数据不一致，让玩家重发即可。
换成库表要多处理过期清理和并发确认，收益是"跨实例"——v1 单实例，不需要（D23）。

## 五、定时结算（全服批处理）

**心跳已经就位**（D48）：`scheduler.rs` 是一个 tokio 后台任务，60 秒一个 tick
（`MissedTickBehavior::Skip`，巡检慢了不补帧），每轮纯读一次 `系统状态`
（D46，不开事务）；第一个 tick 立即触发，进程重启后的第一次巡检天然就是
"启动先补算"的入口。补算本体（开事务 → `锁定状态` → 补 → 写回 → 提交）随 S4 进来。

三个任务，都是"给所有人推进一格"，一条 SQL 覆盖全服：

| 任务 | 频率 | SQL |
|---|---|---|
| 生产次数 +1 | 每小时 | `UPDATE 玩家 SET 生产次数 = LEAST(8, 生产次数 + $1)` |
| 今日招募清零 | 每天 0 点 | `UPDATE 玩家 SET 今日招募数量 = 0` |
| 联军日结 | 每天 0 点 | 先把 `当天资本增量` 落一行进 `联军资本增量`，再清 `当天资本增量`、`当天扩军累计` |

联军日结的 SQL（一个事务，`$1` 是该日的日界 Unix 秒）：

```sql
INSERT INTO 联军资本增量 (联军_id, 日结时间, 资本增量)
SELECT id, $1, 当天资本增量 FROM 联军 WHERE 当天资本增量 > 0
ON CONFLICT (联军_id, 日结时间) DO NOTHING;

UPDATE 联军 SET 当天资本增量 = 0, 当天扩军累计 = 0 WHERE 当天资本增量 > 0 OR 当天扩军累计 > 0;
```

> `ON CONFLICT DO NOTHING` 让日结**可重入**：进程在 insert 之后、update 之前被杀，
> 下一轮重跑不会写出两行（主键 `(联军_id, 日结时间)` 是最后一道闸）。
> 漏跑好几天时只补一行（日期取补算那一刻），因为 `当天资本增量` 只有一份，没法按天拆回去。

约定（理由见 decisions.md D32）：

- **不按人存锚点**。进度在 `系统状态` 那张单行表里：`上次生产结算`、`上次日结`。
- **启动先补算**：`漏掉的小时数 = (now - 上次生产结算) / 3600`，
  一条 UPDATE 补上，再把 `上次生产结算 += 漏掉小时数 × 3600`——**余下的分钟不丢**。
  进程在结算点没跑（部署、崩溃）不会让玩家永久少结算一次。
- **每 60 秒检查一次，不"睡到整点"**：启动时间不整，睡到整点会错位。
  检查本身只是一次 `系统状态` 查询，成本可以忽略。
- **日界按 UTC+8**（`Asia/Shanghai`）。这是全服唯一的"几点算今天"的定义，
  写成常量，别散在代码里。
- 批处理失败只记日志、不阻塞消息处理，下一轮会补。

## 六、事务编排

**写指令恰好一个事务，纯读不开事务**（读写分流，D46）：

```rust
// 写路径：开事务 → 处理器 → 成功提交、失败回滚（D40/D41）
let 现在 = 时间(时钟::现在());              // 时间注入在开事务之前（D48）
let mut 句柄 = storage::开事务(&状态.池).await?;
let 结果 = 处理器::账号::注册(&mut 句柄, &来信, 现在).await;
match 结果 {
    Ok(文案) => storage::提交(句柄).await?,
    Err(失败) => {
        if let Err(回滚错误) = storage::回滚(句柄).await {
            tracing::warn!(%回滚错误, "回滚失败");
        }
        return Err(失败);
    },
}

// 纯读路径：池上借连接查完就还，不占 BEGIN/COMMIT 的连接租期（D46）
let 绑定 = storage::查绑定(storage::执行者::池(&状态.池), 来信.平台, &来信.用户_uid).await?;
```

- **`server` 不依赖 `sqlx`**：`事务` 是 `storage` 导出的 newtype 不透明句柄，
  `开事务` / `提交` / `回滚` 是仅有的三个动作。"只有 storage 懂数据库"
  由此从纪律变成编译期事实（D45）。
- **处理器不取时间**：`时间` 参数由分发层注入（D48），事务里更不该碰系统时钟。
- 事务里**不 await 任何外部 IO**（HTTP、其它连接），只做数据库操作。
- 跨实体操作（战争改两个玩家 + 一张联军表）用**同一个事务**，失败整体回滚；
  多实体加锁顺序按主键升序（`crates/storage/docs/impl.md` 2.7）。
- 条件更新用 `WHERE 旧值 = $3` 的形式，影响行数为 0 表示并发冲突，重算而不是重试写。

## 七、文案模块

`src/文案.rs` 是**玩家可见文本的唯一出口**。规则：

- 任何 `String` 要发给玩家，都必须由这里产生。
- 排版约定：标题用 `====[标题]====`，字段前缀 `■` / `□`，数值千分位。
- 文案函数接收结构化数据，返回 `String`：

```rust
pub fn 签到结果(获得: i64, 稳定度: i64) -> String
```

现有函数：`注册成功(编号, 地区)`、`已经注册(编号)`、`我的资料(编号, 玩家, 库存, 驻扎地区, 联军)`、
`未注册()`、`频道无地区()`、`不认识的指令()`、`文本过长()`、`重复握手()`、
`消息格式错误()`、`系统开小差()`；辅助：`千分位(i64)`——**一切数值展示都走它**
（负数保留负号，逗号只进数字部分），业务代码里不许手写 `format!("{}", 数值)`。

**只有注册会回显 `P…` 编号**（`注册成功` / `已经注册`）——那是玩家拿到自己凭证的
唯一入口；别人的编号永远不作为参数进文案。

## 八、错误呈现

**分层 + 三张表**（D48，修正 D43 的单一平坦枚举）：

```text
错误
├── 业务(业务错误)        规则拒绝与服务器业务失败——回一条 error，连接不断
│   └── 领域(domain::错误)  "拒绝了什么"归 domain，"怎么说"归这张表
├── 传输(传输错误)        握手、帧、JSON、平台一致——协议层的事
└── 存储(storage::错误)   基础设施失败——唯一的 error 级
```

错误码表仍**只有一份**（D43 的教训保留）：它是 `docs/arch/protocol.md` 错误码表的
镜像。三张表对**每一层**都是穷尽 `match`——加失败时编译器逼着每层一起补：

| 表 | 回答 | 用在哪 |
|---|---|---|
| `错误码()` | 机器可读标签（`not_registered` …） | 回给 Koishi 的 `error.code` |
| `玩家文案()` | 给玩家看的一句话 | 同上，`error.message` |
| `日志级别()` | `debug` / `info` / `error` | 连接层记日志 |

日志级别跟着"谁的错"走，分层之后判断写在层上：传输层全是 `info`（协议违反是
客户端的事）、存储层全是 `error`（真故障），业务层逐变体分——玩家弄错
（未注册）是 `info`，"不认识的指令"是 `debug`，编号用尽才是 `error`。

领域拒绝（`domain::错误`）的码与文案在 `业务错误` 的表里翻译——码是**对外协议**
的词汇，不进 `domain`（那里零依赖，也没有 orphan rule 的位置）；
`物资不足` / `数量溢出` 还没有指令路径产生（S3），码与文案先落到占位，
S3 落地时随 `protocol.md` 一起定稿。

**内部错误绝不把原始信息发给玩家**——那既是泄露面，也是体验灾难。
`玩家文案()` 把它们统一压成"系统开小差了"，原始上下文只进 `tracing`。
