# storage — 持久化层

>
> **表结构与领域类型不在这里定义**，见 [docs/arch/data-model.md](../../../docs/arch/data-model.md)。
> 本文只写"怎么落地"。

## 一、这个 crate 是什么

两件事，只做这两件：

1. 写 SQL。
2. 把数据库行翻译成 `domain` 的类型，以及反过来。

**不写规则**。事务的**机制**在这里（D40/D45），**边界**在 `server`；
读写分流（D46）：**读**查询走 [`执行者`](#21-newtype-执行者与读写分流)（池直查，不开事务），
**写**函数只收 `&mut 事务`——这两件事都是编译期强制的。

## 二、实现约定

### 2.1 Newtype、执行者与读写分流

（历史：D40 用类型别名做"不透明句柄"，D45 改成 newtype——别名不屏蔽底层类型的
固有方法，`状态.池.begin()` 照编译；newtype 之后 `server` 连 `begin` 都够不着。）

`pool.rs` 导出的公共面：

```rust
pub struct 连接池(sqlx::PgPool);                          // Clone；方法不外露
pub struct 事务(sqlx::Transaction<'static, Postgres>);    // 不透明句柄
pub enum 执行者<'a> { 池(&'a 连接池), 事务(&'a mut 事务) } // 读查询在哪跑（D46）

pub async fn 建立连接池(url: &str) -> Result<连接池, 错误>;
pub async fn 迁移(池: &连接池) -> Result<(), 错误>;
pub async fn 开事务(池: &连接池) -> Result<事务, 错误>;
pub async fn 提交(句柄: 事务) -> Result<(), 错误>;
pub async fn 回滚(句柄: 事务) -> Result<(), 错误>;
```

查询函数两种形状：

```rust
// 读：收 执行者。纯读传 执行者::池(&池)——借连接、查完、还，不开事务；
// 事务里的读传 执行者::事务(&mut 事务)——读得到本事务未提交的写入。
pub async fn 查绑定(于: 执行者<'_>, 平台: 平台, 平台_uid: &str) -> Result<Option<绑定>, 错误>;

// 写：只收 &mut 事务。拿连接池直接写库，编译不过。
pub async fn 插入玩家(句柄: &mut 事务, 编号: 玩家Uid, 驻扎地区_id: i64, 创建时间: 时间)
    -> Result<Option<玩家Id>, 错误>;
```

为什么不收泛型 `impl Executor`：`Executor` 同样接受 `&PgPool`，而一次函数调用
可能包含**多条**语句——收连接（或事务句柄）就保证它们要么整体在一个事务里，
要么是调用方明确表态"这条只读"；本 crate 不接受裸池打进来写。

### 2.2 行类型与领域类型分开（防腐层）

`src/rows.rs` 集中放行类型与转换，规则有三：

- 行类型 `#[derive(sqlx::FromRow)]`，字段名 = 列名，`pub(crate)`，绝不带 `Serialize`；
- `domain` 的实体**绝不**带 `FromRow`；
- 转换写成 `TryFrom<玩家行> for 玩家`，**所有窄化校验集中在这里**：
  `BIGINT → u8` 等有损转换不允许 `as`，超范围 = `错误::数据损坏 { 表, 列 }`，
  宁可报错不静默截断；词表列（`联军职务` 等）在这里过 `解析`，未知编码同罪。

查询函数不解裸元组：加一列只改行类型 + 转换两处，不碰调用方。
`SELECT *` 的结果集里多出来的列（如 `创建时间`）`FromRow` 按列名取值会忽略——
实体不带的列就不进行类型。

### 2.3 中文字段与中文列名

已实测可行（见 [decisions.md D10 / D20](../../../docs/decisions.md)）：

- `#[derive(sqlx::FromRow)]` 吃中文字段名 ✓
- 中文列名在 SQL 里**不写双引号** ✓（PG 只折叠 ASCII 大写字母，中文原样保留）

### 2.4 条件更新

并发安全靠"旧值作为条件"，不靠锁：

```sql
UPDATE 玩家 SET 私军 = $1 WHERE id = $2 AND 私军 = $3
```

影响行数为 0 表示有人先改了 → 返回 `错误::并发冲突`，由 `server` 重读重算。
例外：`系统状态` 单行表的结算走 `FOR UPDATE` 行锁（见 2.6）——
那是"全服同一时刻只该有一个结算在跑"的谓词，条件更新表达不了。

### 2.5 库存按所有者整体读

一次查出一个所有者（玩家 / 联军 / 地区）的**全部物品**，不要按物品逐个查：

```rust
pub async fn 查库存(于: 执行者<'_>, 所有者: 库存所有者) -> Result<库存, 错误>
```

**读路径已完成**（S3，`我的资料` 的背包展示是第一个用户）；写回（存入 / 取出 /
掠夺）随 S4+ 落地，届时只提交变化的物品行（在 `&mut 事务` 上）。
理由见 [decisions.md D18](../../../docs/decisions.md)：
一次掠夺要搬多种物品，零散查会变成 N 次往返，还会留下"搬了一半"的中间状态。
未知物品编码按 [`错误::数据损坏`] 处理——词表在 `domain`，库里出现它不认识的编码就是损坏。

### 2.6 系统状态：定时结算的串行化点

`src/system.rs`，对应单行表 `系统状态`（D32）：

```rust
pub async fn 查状态(于: 执行者<'_>) -> Result<系统状态行, 错误>;
pub async fn 锁定状态(句柄: &mut 事务) -> Result<系统状态行, 错误>;  // SELECT … FOR UPDATE
pub async fn 写状态(句柄: &mut 事务, 行: 系统状态行) -> Result<(), 错误>;
```

S4 的后台结算形状：`开事务 → 锁定状态 → 按时间差补算 → 写状态 → 提交`。
两个结算并发时，后到者在 `锁定状态` 等前者提交，再基于新进度补算，不会重复加次数。
**补算与写回必须在同一个事务里**，否则锁白拿。

### 2.7 锁顺序（写死，防死锁）

未来"战争结算 / 联军划拨"会在一个事务里改多个玩家、地区、联军与库存行。
**加锁顺序一律按实体主键升序**（`玩家.id` → `地区.id` → `联军.id` → 库存行按
`(所有者类型, 所有者_id, 物品)` 升序）；后台结算与指令事务都遵守同一顺序，
死锁在结构上就不会发生。实现跨实体写函数时，SQL 里的表顺序照这条排。

### 2.8 测试播种：`测试辅助` 模块（feature `testing`）

`src/testing.rs` 只在 feature `testing` 下编译（生产构建不包含），
`server` 的 dev-dependencies 以 `storage = { features = ["testing"] }` 启用。
提供：`播种注册环境`（幂等建地区 + 绑频道 + 清账号，全程一个事务）、
`清理账号`、以及断言用的只读查询（`查绑定编号` / `查驻扎地区` / `绑定条数`）。

历史：S2 时代 `server` 在 dev-dependencies 里挂 `sqlx`、测试自己写 SQL——
改一次表结构两处崩（D47）。现在 `server` 的依赖树里**没有 sqlx**，
"只有 storage 懂数据库"对测试同样成立。

## 三、迁移

- 位置：`crates/storage/migrations/`
- 通过 `sqlx::migrate!("./migrations")` 编译期内嵌，启动时自动执行
- 约束：**迁移只增不改**。已提交的迁移文件永远不修改，改结构就加新的
- **一表一文件**：初始建表按表拆开；以后每张表的演进沿自己的文件序号往后加。
  一张表的历史应该能单独读完，不要把七张表塞进一个文件

| 文件 | 内容 |
|---|---|
| `01_domains.sql` | DOMAIN：`非负计数` / `时间戳` / `可空时间戳` / `百分比` / `六位编号` / `权限等级` |
| `10_coalition.sql` | `联军`（含公开 `uid`、宣称人口/兵力、税率、扩军计划、政治体制、首都） |
| `11_player.sql` | `玩家` + `玩家_联军_id` / `玩家_驻扎地区_id` 索引 + 元首/总理两条部分唯一索引 + 职务与等级一致性 CHECK |
| `12_coalition_allocation.sql` | `联军分配记录` + `(联军_id, 时间 DESC)` 索引 |
| `13_coalition_capital.sql` | `联军资本增量`（一天一行，主键 `(联军_id, 日结时间)`） |
| `20_region.sql` | `地区` + `地区_控制方_联军_id` 索引 |
| `21_region_building.sql` | `地区建筑` |
| `30_inventory.sql` | `库存` |
| `40_platform_binding.sql` | `平台绑定` + 两条唯一约束（`(平台, 平台_uid)`、`(玩家_id, 平台)`） |
| `41_channel_binding.sql` | `地区频道绑定` + 索引 |
| `50_system_state.sql` | `系统状态`（单行：全服结算进度） |

文件名格式：`<两位版本号>_<英文短语>.sql`。

- **版本号必须 ≥ 1**：sqlx 的约定是"文件名前缀是大于零的整数"，`00_` 虽然当前能跑，但属于契约外用法。
- **按 10 分段预留空位**：1x 是联军与玩家，2x 是地区，3x 是库存，4x 是平台/频道绑定。
  一个分段用完（比如 19 之后还要往 1x 里插），才动下一段的号。
- **文件名是 ASCII 英文，SQL 内容与数据库标识符仍是中文**：文件名要过命令行、日志、
  `_sqlx_migrations.description`，保持 ASCII 更省事；表名和列名不受影响。

写法（照 `10_coalition.sql` 抄）：

- 中文标识符**不写双引号**，也不凑列对齐——字段名、类型、约束之间只有一个空格
- 字段语义用 `COMMENT ON TABLE/COLUMN` 写进数据库目录（`\d+ 玩家` 就能看到），
  不塞在字段列表中间当注释
- 计数 / 时间 / 百分比一律用 DOMAIN，不在列上重复 `NOT NULL DEFAULT 0 CHECK (…)`

两个入口（见 `src/pool.rs`）：

```rust
pub async fn 建立连接池(url: &str) -> Result<连接池, 错误>;
pub async fn 迁移(池: &连接池) -> Result<(), 错误>;
```

`建立连接池` 和 `迁移` 都由 `server` 在启动时调用，本 crate 不读环境变量、不自己启动。
`sqlx::migrate!` 的内嵌由单元测试 `迁移文件已内嵌` 守住——路径写错在 `cargo test` 就会失败，
不用等到连上数据库。
